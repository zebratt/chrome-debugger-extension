# ADR-0001：本地浏览器 agent 的公开接口与信任边界

**Status:** Accepted
**Date:** 2026-09-29

## 背景

项目需要让当前 macOS 登录用户下的多个本地 agent 复用已运行的 Chrome。Chrome Native Messaging 是扩展与指定本地宿主之间的标准输入输出通道，不能直接充当任意本地进程的公共服务接口。公开合同一旦被 CLI、MCP 和第三方 agent 使用，破坏性修改的迁移成本较高，属于需要提前明确的一次性方向决策。

## 决策

公开版本化的 JSON-RPC 2.0 合同，通过当前用户专属的 Unix socket 提供服务。CLI 与 MCP 是同一合同的适配器；Native Messaging 只承担扩展与小宿主之间的内部传输。小宿主可随 Chrome 保持连接；broker 由 agent 请求按需启动，空闲退出。

访问边界为**当前 macOS 登录用户**：broker 校验 Unix socket 对端 UID，不进行逐 agent 配对或令牌认证。默认允许普通 `http`/`https` 网站，限制浏览器内部页面、`file://` 和无痕标签页；原始 CDP 子集透传默认关闭，只有修改用户本地策略后才能开启指定协议域。所有客户端均须遵守相同的站点策略和标签页写入占用权。

公开合同从版本 1 开始，主版本表示不兼容变更，次版本只添加可选字段。协议方法、响应、错误、占用权及结果未知语义以方案和 schema 为准。扩展 ID、二进制安装路径与浏览器控制实现均隐藏在合同之后，可独立更换。

## 后果

**收益：** 其他 agent 不必依赖 ChatGPT 的私有扩展或重新启动 Chrome；MCP、CLI 与直接 socket 客户端共享一致的错误与版本语义；broker 可以按需运行。

**代价：** 需要维护小宿主、broker、扩展和公开 schema 的兼容关系；首次安装需加载未打包扩展并注册实际扩展 ID。

**已接受风险：** 当前用户下的任意进程可通过公开接口读取或操作该用户已登录的网页。系统用户之间由文件权限和 UID 检查隔离；同一 UID 内不提供安全隔离。Chrome 扩展的 `debugger` API 只支持部分 CDP 协议域，公开合同不承诺完整 CDP。

## 备选方案

- **直接开放 CDP 端口：** 协议能力更完整，但通常需要以远程调试参数启动 Chrome，不符合复用现有实例的目标。
- **让 Native Messaging 宿主直接服务所有 agent：** 进程更少，但宿主会随 Chrome 常驻并承担 broker 调度，不符合按需 broker 的已确认生命周期。
- **扩展轮询本地服务以实现零空闲进程：** 可避免常驻小宿主，但引入唤醒延迟和恢复复杂度；用户已接受小宿主保持连接。

## 重新评估条件

- 必须支持跨系统用户或远程机器访问，需要重新设计认证与传输边界。
- 必须调用 `chrome.debugger` 不支持的 CDP 域，需要评估受控外部 CDP 路径。
- 本机验证表明在运行中的 Chrome 无法完成扩展与宿主注册，需要重新评估“不重启 Chrome”的交付目标。
